# Ranking Methodology

This project produces two intentionally distinct rankings.

1. **People's Rankings** — the live, crowd-sourced ranking shown in the app.
2. **Offline composite ranking** — generated by the Python scripts in `scripts/`.

This document covers both, with the offline composite (current: **V3**) described in
detail since it's the more involved system. The in-app methodology is also summarized
on the app's Methodology page.

---

## 1. People's Rankings (in-app)

The app's People's Rankings use an **ELO rating algorithm**, similar to chess and
competitive gaming. Each player starts at a base rating that adjusts based on
head-to-head results from real user votes in the daily game, weighted by statistical
performance. Aggregated across all users site-wide, this produces a crowd-sourced
ranking of who fans think is best right now.

The Ringer's [NBA Top 100](https://nbarankings.theringer.com/) is referenced only as
an external expert benchmark to compare against — it does not feed the ELO model.

Player stats throughout the app come from
[Basketball Reference](https://www.basketball-reference.com), focused on recent
regular-season performance to answer "who's best right now."

## 2. Offline composite ranking (V3 — current)

`scripts/generate_player_rankings_v3.py` generates a transparent, fully objective
composite ranking from Basketball Reference advanced stats.

### What's different in V3

- **One row per player** (current season), instead of one row per player-season.
- **Historical data as features** — the last 3 years are aggregated into columns
  rather than separate rows.
- **Playoff weighting** — current-season playoff stats weighted 2x.
- **Direct H2H win %** exposed as a primary metric.

### Final score formula

```
Final Score = (Current Season × 60%)
            + (Historical       × 30%)
            + (H2H Win Rate     × 10%)
```

**Current Season (60%)** — current regular season + playoffs, with playoff
GP/GS/MP weighted 2x. Composite of PER, BPM, VORP, WS/48, TS%, OBPM, DBPM, USG%
(z-score normalized).

**Historical (30%)** — aggregated over the previous 3 seasons:
- Avg BPM (40%)
- Trajectory / trend slope (20%)
- Playoff experience score (20%)
- Consistency (20%)

**H2H Win Rate (10%)** — direct Monte Carlo simulation results (see below),
average win probability vs all opponents.

### New historical feature columns

| Column | Description |
|--------|-------------|
| `Seasons_Played` | Number of seasons in last 3 years |
| `Total_Games_Last_3Y` | Total regular-season games |
| `Total_Playoff_Games_Last_3Y` | Total playoff games |
| `Avg_BPM_Last_3Y` / `Avg_VORP_Last_3Y` / `Avg_PER_Last_3Y` | 3-year averages |
| `Peak_BPM_Last_3Y` | Best BPM in last 3 years |
| `Trajectory_Last_3Y` | Performance trend slope (positive = improving) |
| `Playoff_Experience_Score` | Recency-weighted playoff experience |

## Shared component details

### Composite statistical score

Weighted, z-score–normalized combination of advanced metrics:

| Metric | Weight | Description |
|--------|--------|-------------|
| BPM | 20% | Box Plus/Minus (overall impact) |
| VORP | 20% | Value Over Replacement Player |
| PER | 15% | Player Efficiency Rating |
| WS/48 | 15% | Win Shares per 48 minutes |
| TS% | 10% | True Shooting Percentage |
| OBPM | 7.5% | Offensive Box Plus/Minus |
| DBPM | 7.5% | Defensive Box Plus/Minus |
| USG% | 5% | Usage Rate |

Each metric is converted to a z-score `(value - league_mean) / league_std`, summed by
weight, then scaled by a **playing-time reliability factor** so small samples don't
dominate:

```
Minutes Factor = min(1.0, Total_MP / 500)
Starts Factor  = min(1.0, Total_GS / 20)
Games Factor   = min(1.0, Total_G  / 30)
Playing Time Factor = (Minutes × 0.5) + (Starts × 0.3) + (Games × 0.2)   # floor 0.3
```

### Playoff weighting

Playoff volume counts double, and advanced stats are minutes-weighted with playoff
minutes counting 2x:

```
Total_G  = Regular_G  + (Playoff_G  × 2)
Total_GS = Regular_GS + (Playoff_GS × 2)
Total_MP = Regular_MP + (Playoff_MP × 2)

Combined_Stat = (Regular_Stat × Regular_MP + Playoff_Stat × Playoff_MP × 2)
                / (Regular_MP + Playoff_MP × 2)
```

Rationale: playoff competition is higher and more predictive of true skill.

### Head-to-head win rate (Monte Carlo)

For each matchup between Player A and Player B:

```
Offense = (PER × 0.3) + (OBPM × 5) + (TS% × 50) + (USG% × 20)
Defense = (DBPM × 5) + (STL% × 100) + (BLK% × 100)
Impact  = (BPM × 2)  + (VORP × 5)  + (WS/48 × 50)
Total   = Offense + Defense + Impact
```

Run ~500 simulations per matchup, sampling from `N(Total, Total × 0.15)` to model
game-to-game variance, and count A's wins. A player's H2H win rate is their average
win probability across all opponents.

### Historical trajectory

Fit a linear trend to a player's BPM across available seasons; the slope is the
trajectory (positive = improving, negative = declining). Requires ≥2 seasons; missing
seasons are ignored.

## Output files

The V3 generator writes:

- `player_rankings_24-25_v3.csv` — full rankings, one row per player, all columns
- `player_rankings_top100_24-25_v3.json` — top 100 for frontend integration
- `rankings_summary_24-25_v3.json` — methodology + top performers

JSON summary includes the weight distribution
(`current_season_weight: 0.60`, `historical_weight: 0.30`, `h2h_win_rate_weight: 0.10`).

---

## Running the generator

```bash
python scripts/generate_player_rankings_v3.py
```

**Required data** (`data/`): `Bbref_Adv_*.csv` and `Bbref_Playoff_Adv_*.csv` for the
current and prior 3 seasons. **Optional:** `ringer_top_100.csv` for benchmark
comparison. Runtime is ~5-10 minutes (dominated by H2H simulations).

Dependencies: `pandas`, `numpy` (plus stdlib `json`, `datetime`, `pathlib`).

## How this compares to The Ringer

| Aspect | This system | Ringer Top 100 |
|--------|-------------|----------------|
| Data source | Basketball Reference stats | Expert panel + stats |
| Subjectivity | Fully objective | Subjective elements |
| Playoff weight | 2x multiplier | Unknown |
| H2H | 500-sim Monte Carlo | N/A |
| Transparency | Fully documented | Limited |

Expected divergences: the model is stats-driven, so it may rate young players lower
(no "potential" credit), veterans by trajectory rather than reputation, and
specialists by efficiency rather than intangibles.

---

## Known limitations

- Early-season samples are volatile (mitigated, not eliminated, by minimum thresholds).
- Context-blind: no team-quality, coaching-system, or injury adjustments.
- Linear trajectory can miss non-linear career arcs.
- Position bias: centers naturally lead some metrics (blocks/rebounds); guards may be
  undervalued defensively.

Possible future work: position-adjusted weights, team-context adjustment, clutch/
late-game weighting, confidence intervals, and playoff-round weighting.
